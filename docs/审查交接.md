## 一句话

浏览器里的代码编辑器。纯静态，无后端无构建，GitHub Pages 托管。
**代码不上传服务器，执行只在用户浏览器里。**

## 文件分工

| 文件 | 职责 |
|---|---|
| `js/langs.js` | 语言注册表：谁能跑、怎么跑、属于哪一档 |
| `js/runtimes.js` | 按需运行时的**主线程侧**：起 Worker、转发、进度 |
| `js/rt-worker.js` | **Worker 侧**：加载并执行六种运行时 |
| `js/runtime.js` | 只查不写：清单、体积、缓存状态 |
| `js/runner.js` | 转发到 `runtimes.run`，把结果打到面板 |
| `js/pylite.js` / `js/cpplite.js` | 自研 Python / C++ 子集解释器 |

**只有一套下载与执行链路。** 曾经有过两套，已合并——断言会挡住第三套。

## 三档能力

| 档 | 语言 | 依赖 |
|---|---|---|
| 内置自研（零依赖·离线） | JavaScript（原生）、HTML、Python 子集、C/C++ 子集 | 无 |
| 按需下载（真 WASM） | SQLite、Lua、CPython、PHP、Ruby、Clang | assets 库 Release |
| 仅着色 | JSON/CSS/Markdown/YAML/Shell | 无 |

Python 与 C++ 是「自研 + 可升级」：子集立刻可用，下载后自动切真的。

**真机遇到任一语言加载失败时，请先取证再回头对照。** 打开 DevTools → Network，
对失败的那条资源记录三行：

1. **最终 URL** —— 是否 302 跳到了 `objects.githubusercontent.com`（对应风险 3）
2. **响应头 `Content-Type`** —— 若是 `application/octet-stream` 等非法 JS MIME，

## 我最不放心的四处

1. **ESM 的 MIME type** — `ruby-wasi.js`、`cpp-index.js` 走动态 `import()`。
   GitHub 直链若返回 `application/octet-stream`，浏览器会**直接拒绝**。
   这条我验不了，只能真机看。

2. **`import.meta.url`** — browsercc 的 `compile()` 内部用
   `new URL("sysroot.tar", import.meta.url)` 取 sysroot。
   所以必须 import **原始直链**，不能包 blob URL（会变 `blob:`，相对解析崩）。
   已按此实现，但没跑过。

3. **重定向漏缓存** — GitHub 直链会 302 跳到 `objects.githubusercontent.com`，
   重定向后 URL 不再以 `BASE` 开头，只看前缀会漏掉 —— 27.3 MB 的 sysroot 每次重下。
   已加按文件名兜底（`KNOWN_NAMES` / `cacheUrlFor`），未验证。

4. **`file://` 下 Worker 被拒** — 直接影响「本地与线上一致」这条硬约束。
   已补 `server.py`（`python3 server.py` → `http://localhost:8000/`），需真机确认能否绕过。

## 三条设计决定，改前请先看

1. **接管了 Worker 里的 `fetch`** — pyodide 拿到 `indexURL` 后自己去 fetch
   `pyodide.asm.wasm` 和 stdlib，sql.js 的 `locateFile` 同理。
   不接管，它们会绕过缓存每次重下。

2. **URL 编码：`+` 必须是 `%2B`** — `ruby+stdlib.wasm` 在 Release 直链里是
   `ruby%2Bstdlib.wasm`。下载和清理曾是两个 key，表现为"清理了但还在"。
   已统一到 `urlOf()`，断言禁止裸的 `BASE +` 拼接。

3. **SHA-256 取 Release API 的 `digest` 字段** — 不要抄 `assets/manifest.json`，
   那份是抓取脚本生成的、不全（只有 3 条，Release 里有 23 个）。
   人工抄哈希错一位，"校验通过"就成了谎言。
