# Code · 原生端（Android）

## 先说清楚：什么才算"不是套壳"

**套壳 = 整个界面是网页**，原生只是个装网页的盒子（WebView 加载 `www/`）。

本目录**不是**那个。判断依据（都能直接查）：

| 检查项 | 结果 |
|---|---|
| 有没有 WebView | **零个**。全仓无 `WebView` / `webView` / `loadUrl` |
| 界面用什么写 | 全部 Jetpack Compose（Kotlin） |
| 键盘 | 原生 Composable，不是 DOM |
| 联网权限 | **没申请**（见 AndroidManifest） |
| 文件存储 | 内部存储 + Room（后续） |

最后一行那条最直白：**一个不联网的编辑器，不可能是在加载远程网页。**
不联网是"本地优先"的证明，不是功能缺失。

### 虚拟键盘：为什么它最该做成原生

1. 系统输入法根本不适合写代码——没有 Tab、方向键、括号补全，还会自动纠错联想。
2. **Web 端只能"绕过"它**（`js/vkeyboard.js` 553 行干的就是这个），
   原生可以从源头解决：**根本不让它弹出来**。
   关键一行在 `EditorScreen.kt`：`LocalTextInputService provides null`，
   输入法平台通道压根不启动。
3. 手感是 Web 给不了的：触觉反馈、精确按下状态、长按重复节奏。

键位沿用 Web 版（abc / 符号 / 功能 三页，用户已熟悉），**实现全部重写**——
DOM 那套逻辑在原生侧没用。

### 编辑器操作（纯函数，已测 24/24）

`EditorOps.kt` 全部是不碰 UI 的纯函数，可以脱离模拟器测试：

- **括号自动配对**：输入 `(` 补 `)`，光标停中间；光标右侧已有 `)]}>` 或空白时不重复补
- **退格删整个缩进**：4 空格一次删掉，不用按 4 次
- **回车继承缩进**：行尾是 `{` `:` `(` `[` 时多缩进一级
- **Home 两级**：第一次到缩进之后，再按才到行首
- **上下移动保持列号**，目标行短则夹住

## ⚠ 必须说清的三件事

### 1. 没有编译过

**这个环境里没有 Android SDK / kotlinc，一行都没编译过。**
语法与 API 用法是按 Compose 现行 API 写的，但**未经验证**。

已验证的只有 `EditorOps` 的**算法**——用 Python 复刻同样逻辑跑了 24 个用例
（`tests/editor-ops-test.py`）。这能证明逻辑对，不能证明 Kotlin 能编译。

要在 Android Studio 里打开 `native/android` 才能真正验。

### 2. 运行时还没接

这是**真实的架构矛盾，别绕过去**：

| 运行时 | 形态 | 原生要什么 |
|---|---|---|
| 官方 pyodide / clang | **WASM** | 需要 wasm 引擎（wasmtime / wasmer），包体与构建复杂度上一个量级 |
| cpplite / pylite（我写的） | **JavaScript** | 需要 JS 引擎（QuickJS 0.5 MB） |

二者**不可兼得**：你已经拍板用官方运行时，而官方运行时是 WASM。
所以原生端要么引入 wasm 引擎，要么放弃官方运行时用 cpplite/pylite。

我的建议：**第一阶段先都不带**（就是现在这样）。
先验证原生骨架，等 Web 端把官方运行时真跑通一次，再决定迁哪个——
那时才知道值不值这个体积。

### 3. 文件写入用"临时文件 + rename"

```kotlin
tmp.writeText(content)
tmp.renameTo(f)   // 同分区内是原子操作
```

写一半断电不会把原文件弄坏。rename 之前原文件始终完整。

写入失败**必须抛 IOException**，不能吞——
调用方靠它显示"保存失败：…请改用导出备份"。
吞掉异常 = 静默失败 = 用户以为存了其实没存。

## 关于"用 QuickJS 跑 cpplite 算不算套壳"

**不算。** 套壳指的是**界面**是网页。

UI 全原生、不加载任何网页的前提下，用 QuickJS 跑解释器内核，
和用 SQLite 存数据是同一性质——没人会说"用了 SQLite 就是套壳"。
引擎是零件，不是外壳。

这话现在写在这里，是因为后面一定会有人（包括我）再纠结一次。
