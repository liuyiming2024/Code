# 关于「爬题目 + 代提交」

结论先说：**不做代提交**。做了**本地判题**（已上线，底部面板「判题」页签）。

## 为什么不代提交

| 问题 | 说明 |
|---|---|
| 反爬与人机验证 | 主流 OJ 都有 Cloudflare / 验证码。爬虫是与它们持续对抗，随时失效 |
| 平台条款 | 用用户自己的账号代提交，多数平台的服务条款不允许 |
| **凭据风险（最要紧）** | 一旦我们存了用户的 OJ 密码，它就变成有价值的攻击目标。而本项目是纯前端、**没有后端**，本来没有任何东西值得偷 |
| 结果不可信 | 爬回来的判定依赖对方页面结构，改版就失效；判错比不判更糟 |

第三点特别说明：一个"存了用户 OJ 密码的前端项目"和一个"什么都不存的前端项目"，
风险量级完全不同。现在的设计不持有任何第三方凭据，这个性质不要丢。

## 做了什么：本地判题

竞赛选手真正高频的需求不是"提交"，而是**写完立刻知道样例过没过**。

- 多组样例，逐组比对
- 第几组错、期望什么、实得什么，直接列出
- 超时 / 运行出错分开判定（TLE 与 WA 长得完全不一样）
- 样例按文件存，切回来还在
- 用与「运行」**同一套**解释器，不会出现"运行是对的、判题说错"

比对时忽略行尾空格、末尾多余换行、`\r\n` ——
这三条不处理会大量误报 WA，用户会去查根本不存在的算法错误。

## 如果将来确实想接平台

只走**官方公开 API**，且：

1. 用户自己填自己的 API key，**我们永不保存**（只存 localStorage，不上传）
2. 不做页面爬取
3. 只在平台明确允许自动化提交的前提下做

即便如此，先把本地判题用顺手 —— 提交前的那一步，才是真正花时间的地方。
