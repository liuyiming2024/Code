# 做题平台：本地判题 与 远程代提交

本仓库现在有两块：**本地判题**（默认、无风险）与**远程代提交**（需自行开启、自担风险）。

---

## 免责声明（远程代提交）

> **使用远程代提交功能即表示你已阅读并同意以下内容。**

1. **自动化提交可能违反目标平台的服务条款。** Codeforces、洛谷、HDU 等平台
   各自有使用规则，其中部分平台明确限制自动化/脚本提交。
2. **后果由你自行承担。** 可能包括：提交被限流、账号被警告、
   **账号被封禁**、比赛资格受影响。本项目不对这些后果负责。
3. **你用的是自己的账号。** 凭据（cookie）由你自行提供，
   提交行为在目标平台看来**就是你本人操作的**。
4. **凭据只存在你这台设备的浏览器里。** 转发服务是**无状态**的：
   收到请求、转发、返回结果，**不写库、不写日志、不保存**。
   但你的凭据会经过我们的转发服务，这一点不隐瞒 ——
   因为浏览器无法跨域带 cookie（CORS + 同源策略），**没有转发层就做不了**。
5. **本功能默认关闭**，需要你主动勾选「我已知悉风险」才能使用。
6. **如果平台要求人机验证，提交会失败** —— 这是预期行为，不是故障。

**不确定的话，就用本地判题。** 提交前那一步才是真正花时间的地方。

## 一、本地判题（推荐）

竞赛选手真正高频的需求不是"提交"，是**写完立刻知道样例过没过**。

- 多组样例逐组比对，报第几组错、期望什么、实得什么
- 超时 / 运行出错分开判定（TLE 与 WA 长得完全不一样）
- 样例按文件存，切回来还在
- 用与「运行」**同一套**解释器，不会出现"运行是对的、判题说错"

比对时忽略行尾空格、末尾多余换行、`\r\n` ——
不处理会大量误报 WA，让人去查根本不存在的算法错误。

## 二、远程代提交

### VJ 为什么能做到

VJ 有**真正的后端服务器**，并用两种方式提交：
- 机器人账号池（CF 上的 vjudge1/vjudge2、HDU 上的张翼德/马孟起）
- 用户自绑账号（你在 VJ 提供自己的 cookie）

代价已经发生了：**Codeforces 已封禁 VJudge 的机器人账号**，
VJ 官方现在也改成让用户绑定自己的账号。

### 我们怎么做

| | VJ | 本项目 |
|---|---|---|
| 后端 | 自建服务器 | Supabase 转发函数 |
| 凭据保存 | **存进自己的数据库** | **不保存**（无状态转发，用完即弃） |
| 提交账号 | 机器人池 / 用户账号 | **只用你自己的账号** |

**没有机器人账号池** —— 我们不注册一批号去替所有人提交。
那会让别人的封号风险落在我们控制不了的账号上，也不符合上面第 2 条。

### 需要你做一次的事

1. 登录目标平台
2. 按 F12 打开控制台
3. 执行 `document.cookie`，把输出粘到「凭据」框
4. 勾选「我已知悉风险」
5. 填题号、选语言、提交

凭据存在你自己的 localStorage，下次打开还在。

### 目前支持

- **Codeforces**（题号如 `4A`）

其他平台没做就明说没做 —— 假装支持的话，提交了永远等不到结果，比不支持更糟。

### 部署转发服务

```bash
supabase functions deploy oj-proxy
```

不部署的话，「提交」会提示连不上服务，**代码不会被提交**（这一点在界面上明确写出）。

### 语言与文件要匹配

拿 `.py` 的源码按 G++ 提交必然编译失败，而这个错看起来像"平台判错"。
所以提交前会检查，不匹配就拦下来。
